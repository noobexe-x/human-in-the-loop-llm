# dbtesttools

開発・デモ用の手動テストツール置き場です。本番アプリの起動処理には含めません。

| ファイル | 用途 |
|---|---|
| `clear_business_data.py` | ユーザーを残したまま、AI生成履歴と判定履歴を削除する |
| `seed_fake_data.py` | DBへ直接デモ用ユーザー、AI生成履歴、判定履歴を投入する |
| `frontend_flow_test.py` | フロント経由でログインし、AI質問と4段階判定を実行する |
| `dirty_data_test.py` | ランダムな汚れデータをETLとフロント経由判定へ注入する |

## テスト規約

- テストケースは固定値だけで組まず、`random` や `Faker` を使ってランダムな形で注入する。
- テスト用のユーザー名、質問文、AI候補、判定理由、ログ確認用テキストは、原則としてすべて日本語にする。
- 権限・ログイン処理は既存の `frontend_flow_test.py` の版型に合わせる。
- 権限ありユーザーと権限なしユーザーの確認では、次のテストユーザーを使う。

| 種別 | ユーザー名 | パスワード | 用途 |
|---|---|---|---|
| 権限ありユーザー | `藤井修平` | `123456` | フロント経由のAI質問・4段階判定テスト |
| 権限なしユーザー | `藤原翔太` | `123456` | ログイン後の利用制限テスト |

`frontend_flow_test.py` と `dirty_data_test.py` の通常ユーザー設定は次を基準にする。


- インターフェース検証は複雑にしすぎず、フロント経由の最小フローで確認する。

## 使い分け

- 画面表示用のデータをすばやく用意したい場合は `seed_fake_data.py` を使う。
- 実際のログイン、AI生成、判定保存の流れを確認したい場合は `frontend_flow_test.py` を使う。
- ランダムな汚れデータの清洗と保存結果を確認したい場合は `dirty_data_test.py` を使う。
- デモ前に業務データだけを消したい場合は `clear_business_data.py --yes` を使う。
